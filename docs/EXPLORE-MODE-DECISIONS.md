# Explore mode — decision log

Every judgement call made during the Explore mode build, written down as it
was made.

**Append to this file the moment a decision is made.** Not at the end of a
sprint, not at the end of the run. A run this long loses context, and a log
reconstructed from memory afterwards is a fiction — it will be confidently
wrong about the reasoning, which is the only part worth keeping.

The last column is the one that matters. It is what lets the owner overturn a
decision without having to reverse-engineer it first: what it would cost, and
what he would get instead. A row without a real answer there is not finished.

Rules for this file:

| | |
|---|---|
| One row per decision | Not per commit, not per sprint |
| Small decisions belong here too | The point is a complete record, not a highlights reel |
| Escalated decisions belong here | With what the owner said, so the reasoning survives |
| Never edit a row after the fact | Add a new row that supersedes it, and say so |

| 1 | 0 | Work on `claude/spaces-lab`, as instructed, not on the session's default branch `claude/spaces-lab-lk3n7u` | The owner named the branch explicitly and it is the one Vercel builds a preview from. Both branches pointed at the same commit when the run started, so nothing was lost | Nothing. `git push -u origin claude/spaces-lab-lk3n7u` from the same commits, one command |
| 2 | 0 | Add a development fixture dataset — `fixtures/dev-buildings.json`, served by `/api/buildings` **only** when `SPACES_FIXTURE_DB=1` | This container has no `DATABASE_URL` and no way to get one. | 3 | 0 | Geometry, BINs, heights, floor counts and years in the fixture are real NYC Open Data. Availability and tenancy rows are invented, and every one carries `FIXTURE — synthetic development data` in its own notes | The plan forbids inventing *product* data. Development scaffolding that never reaches production and is labelled in every row is a different thing, and the alternative was no visual verification at all for the whole run | Point the fixture generator at a read-only copy of the real database instead: ~1 hour, and needs a connection string this container does not have |
| 4 | 0 | The fixture is a fallback for the **flag**, never for a database failure. A missing or broken `DATABASE_URL` still errors exactly as it does today | A broker must never be shown invented availability because a query timed out. Silent fallback is how that happens | None available — this one is not worth overturning |
| 5 | 0 | Baseline recorded as 100 passing / 7 failing browser checks before any Explore code was written. The 7 are `verify-add-by-hand` ×5 (needs database writes) and `verify-map-chrome` ×2 (needs a second tower to land under a projected screen point) | A regression detector needs a known-good starting count. Reporting "7 failures" at the end without this baseline would look like damage caused by this work | Nothing to change; this is a measurement, not a choice |
| 6 | 0 | `three` 0.185.1 (MIT) as the only new runtime dependency | The plan settles three.js. MIT is permissive; the module graph actually imported is roughly 170 KB gzipped, well inside the 5 MB load budget | Nothing else in the plan works without it |
| 7 | 1 | The three.js scene is **metres**, `+X` east `+Y` north `+Z` up, bridged to Mercator by one translate-and-scale in the layer | A mullion is 4e-9 Mercator units, which is past a 32-bit float's resolution. Every shader that wants a distance in metres would otherwise have to undo the projection first | Nothing to change — this is the standard bridge. Moving the anchor is what costs: it is fixed for the layer's life because it is the origin every vertex is relative to |
| 8 | 1 | Camera position derived from MapLibre's **public** accessors (`getCenter`/`getZoom`/`getPitch`/`getBearing`) using its own camera model, not read off `map.transform` | `transform` is not in the published type surface and has changed shape between versions. This project has already been bitten once by building on an internal | Read `map.transform.getCameraPosition()` instead: 5 lines, and it re-couples us to a private field |
| 9 | 1 | three.js **colour management off** for Explore mode | Since r152 `new Color('#8FB4E4')` is converted sRGB→linear while `new Color(0.9,0.9,0.9)` is not. Explore mixes both — sky from the atmosphere presets as hex, stone as numbers — so half the palette was silently a stop and a half dark. The city rendered slate blue and every individual number was correct | Turn management on and convert the numeric colours instead: ~1 hour, same result, more places to get it wrong |
| 10 | 1 | Explore renders **display-referred**: no tone mapping, no sRGB encode | This renderer writes into MapLibre's own drawing buffer and composites under deck.gl, and both write display values with no encode step. Explore has to live in their colour space, not its own | Adding a tone-mapped pass means re-grading deck.gl's bands to match: half a day, and the two modes would then differ in how loud Goldenrod looks |
| 11 | 1 | In Explore mode deck.gl draws **only what belongs on top of the world** — bands (invisible, for picking), name-plates, transit, radius. The ground, the massing, the roofs and the floor lines all move to three.js | deck.gl's overlay is a separate canvas composited above MapLibre's, so anything opaque it draws paints over the three.js city entirely. This is not a preference, it is what the compositing allows | Switch the deck.gl overlay to `interleaved: true` so both share one buffer: ~1 day, and it changes the flat map's render path, which is the thing that must not change |
| 12 | 1 | The buildings layer and the bands layer stay in deck.gl in Explore mode, drawn **fully transparent**, purely to keep them clickable | Picking runs in its own framebuffer and is indifferent to alpha, so every popup, fly-to, hover and Compare behaviour carries over with no changes in either mode. Rebuilding picking as a three.js raycast would be a second implementation of a solved problem | Raycast in three.js and delete the invisible layers: ~1 day, plus re-testing every click path the flat map already proves |
| 13 | 1 | The **visible** availability bands are drawn in three.js, from the same `computeBands()` the flat map calls | With them on deck.gl's canvas every band showed all four sides at once and read as a yellow wireframe box floating beside the tower rather than a stripe on it. That is availability getting *less* legible, which fails the one rule. Same maths means the two can never disagree about a floor | Move them back and accept the floating look: one line. Not recommended — this was the single biggest legibility win in sprint 1 |
| 14 | 1 | A band's collar is taken from the **massing's width at that height**, not the ground footprint (`lib/explore/profile.ts`) | This is §5's argument as code. On a stepped tower a collar drawn on the plot hangs in mid-air above the first setback. The flat map is unaffected: it draws a plain prism, where the footprint is the answer at every height | Drop `profile.ts` and pass the footprint through: 10 minutes, and every band above a setback floats again |
| 15 | 1 | Explore mode's city is **colourless** — colour-by-rent applies to the flat map's massing only | The art direction is explicit that availability, client space and the selection are the only saturated things. A city tinted by rent would be competing with the bands everywhere at once | Tint the stone by rent mode: ~2 hours. It directly weakens the one rule, so it should be a deliberate choice rather than a default |
| 16 | 1 | Glass reflectance is 34% face-on rather than the textbook 4% | A curtain wall is mostly glass, so whatever the glass does the building does. At 4% with a tinted pane the city came out dark slate — striking, and the exact opposite of the brief. Coated architectural glazing really is near a third | Lower it and the city darkens; a dark city makes every lit window compete with the bands |
| 17 | 1 | The harness judges "availability leads" on **chroma**, not brightness | A near-white city in sunlight is legitimately brighter than `#FFB600`. Asserting on brightness would force a grey city and contradict the art direction. What makes a band lead is being the only saturated thing in the frame | Assert on brightness instead and the city has to go grey: the measurement change is 5 minutes, the art direction change is the whole look |
| 18 | 1 | Every setback step gets its own lid, not just the topmost | Capping only the top left a hole at each setback you could see the sky through. On screen it read as the tower coming apart rather than as a missing face, which is why only a screenshot found it | None — this was a bug, not a choice |
| 19 | 2 | `ExploreLayer.projectToScreen` and `.budget` are exposed, and the layer is put on `window.__explore` | Sprint 2's kill criterion is that bands and facades must not disagree about a floor, and that can only be proved by projecting a floor to a pixel and looking at it. A unit test would check the same arithmetic twice | Delete both and the alignment check becomes an eyeball: 10 minutes to remove, and the project loses its only mechanical guard on the thing §5 is about |
| 20 | 2 | The alignment probe is a **storey-tall strip across the near facade**, not a point | A point at the centroid lands a hundred pixels off the band on the near wall; a point at a footprint corner misses a band that has stepped inward above a setback. Both are true facts about geometry and neither is the question, which is purely vertical | None — three cheaper probes were each wrong in a different way |
| 21 | 2 | Projection rejects points with `w <= 0` | A point behind the camera divides to a perfectly plausible on-screen pixel. The harness probed it, found no band, and reported floor 63 broken when it was simply above the top of the frame. `Vector3.applyMatrix4` does that divide silently | None — this was a real bug in the projection helper |
| 22 | 2 | The context city is **one merged mesh**, not one per building | At forty thousand footprints the draw-call budget binds long before the triangle budget: forty thousand meshes is forty thousand state changes a frame against a budget of 1,000. Measured: the whole visible city is 151,179 triangles in **one** call | Split it for per-building culling: ~half a day, and it buys nothing until a single viewport holds more than about 2M triangles, which it does not |
| 23 | 2 | Budget measured, not asserted: **151,179 triangles and 19 draw calls** for the whole visible city with Explore on | §9 asks for it to be validated in sprint 2. It is 7.6% of the triangle budget and 1.9% of the draw-call budget, so the room for glass, interiors and street life is real rather than hoped for | Nothing — this is a measurement |
| 24 | 2 | Frame time is reported as "not pathological", with the reason, rather than as a 60 fps claim | The harness runs on SwiftShader in a container, one to two orders of magnitude slower than a broker's laptop. A 60 fps assertion here would either fail always or be meaningless | Run the harness on a machine with a GPU and tighten the threshold: a config change, but it needs hardware this container does not have |
| 25 | 3 | `scripts/fetch-lod2-massing.ts` gains `--from=<json>`, so the asset can be rebuilt without a database | The BIN list was the only thing the script needed Neon for. A development container, or anyone reproducing the asset from the checked-in fixture, could not run it at all | None — the database path is unchanged and still the default |
| 26 | 3 | A band's ring is a **real cross-section** of the surveyed massing, not a scaled footprint | Three weaker versions were each visibly wrong. A scalar shrink applied about the plot's centroid cannot describe a shaft that is off-centre in its plot or a different aspect ratio from it, and the Empire State Building is both — its bands ended up outside the tower on the short axis and inside it on the long one simultaneously | Revert to `insetForBuilding`: 20 minutes, and every band on a tower with an off-centre shaft goes back to floating |
| 27 | 3 | The cross-section is the **convex hull** of the slice, not a stitched loop | Ordering the segments into a loop needs adjacency the model does not publish, and getting it wrong produces a self-intersecting ring — a bow tie drawn across the building. A hull is always simple, always the right size and place, and a collar wraps the outside of a building anyway | Stitch properly: ~1 day plus a robustness problem. It buys one thing — a courtyard building's band would stop crossing its light well |
| 28 | 3 | Sections are cached per building per metre of height | Band geometry rebuilds on every filter keystroke, selection and colour change, and a slice walks every wall polygon — 469 of them on the Empire State Building | Drop the cache: one line, and filtering becomes visibly slow on a laptop |
| 29 | 3 | Surveyed reach is reported in **metres**, not as a fraction of reach at ground | The footprint dataset and the massing model do not agree about a building's extent at ground level — different surveys, different ideas of where a plinth ends. A ratio between two different measurements compounds the disagreement, and put ESB's bands a fifth of the way inside its own shaft | None — this was a units bug |
| 30 | 3 | The verification probe reads the **massing's** wall position, never the band's | Otherwise the test asks the code where it drew and then agrees with it. Massing and bands are separate code paths — surveyed surfaces or an extrusion, against `computeBands` | None available that is still a test |
| 31 | 4 | A bay is pier, mullion, transom, spandrel and pane — five parts, not two | A single sheet of glass a storey tall and a bay wide exists on very few buildings, and without the divisions a glass tower reads as shrink-wrapped. That is the specific way a procedural facade looks fake | Drop the transom and centre mullion: 20 lines. It costs the close-up view, which is the one this mode exists for |
| 32 | 4 | The mullion is a fixed 90 mm, not a fraction of the bay | Curtain wall is made of extrusions that come in one size. A proportional mullion makes a narrow bay's frame narrow, which no real building does | None worth having |
| 33 | 4 | Lit windows at dusk and night only, off at midday, deterministic per building from its id | A warm speckle across every glass tower in daylight is invisible as an effect and visible as noise, and Goldenrod is supposed to be the only warm thing in the frame. Seeding from the id means the same windows are lit every time the page opens | Light them at all hours: one line. It puts warm colour into the frame the hierarchy has no room for |
| 34 | 4 | The ground plane is lit by the **hour**, not by the light/dark theme | Keyed off the theme it left a near-white pavement under a black sky with a dark city standing on it, which reads as a mistake because it is one | None — this was a bug |
| 35 | 4 | Facade detail is verified against a **control in the same frame** — a patch of bare ground plane — not against an absolute threshold | The first absolute threshold was wrong by a factor of three, in the direction that fails a working feature. The honest question is not "is contrast above N" but "does this surface have structure that a surface without structure does not". Measured: 0.0061 on the wall against 0.0000 on bare ground | Pick a number instead: 2 minutes, and it will be wrong again the next time the lighting changes |
| 36 | 4 | No backticks anywhere in this file's GLSL | The shaders live in template literals, and a backtick in a GLSL comment ends the literal — producing a TypeScript syntax error a hundred lines away from the cause | None — this is a note to the next person |
| 37 | 5 | `lib/roofscape.ts` is reused unchanged; only its *rendering* is promoted | It already derives parapets, tiers, plant, tanks and masts from footprint, height, floor count and year built, deterministically and with no hand authoring. Sprint 5 is a rendering sprint, not a rederivation | None — rewriting it would throw away a tested generator |
| 38 | 5 | On a **surveyed** building the roofscape is derived against the massing's own crown — the largest roof surface and its cross-section — not the plot | A derived roofscape assumes the roof is at `height_roof_ft` with the footprint's outline. On a stepped tower neither is true, and the furniture would float beside the building. Same class of error as a band on the plot | Feed it the footprint: one line, and every water tank on a surveyed tower ends up in mid-air |
| 39 | 5 | The crown is picked by **area**, not by height | On a real tower the topmost surface is a few square metres of antenna cap. Putting the building's plant room on it is absurd in a way that is very easy to ship | Pick by height: one line, and the Empire State Building gets a plant room on its mast |
| 40 | 5 | A parapet is a hollow wall with a coping, not a solid slab | A solid parapet seen from above is a plate covering the roof, which hides the tanks and plant standing on it — the whole reason the roof is worth drawing | Extrude a solid ring: simpler code, and the roofscape disappears from every view above it |
| 41 | 5 | Roof furniture is merged into its building's own mesh | A tower's roof is a dozen small pieces; at 400 buildings that is five thousand draw calls against a budget of one thousand. It shares the building's material anyway — same stone, never coloured by data | Separate meshes for per-piece culling: half a day, and it buys nothing at this scale |
| 42 | 5 | Water tanks are ten-sided, not thirty-two | A tank is a few pixels tall from anywhere this map is read. Its silhouette is the point; smoothness is not | Raise it: one number, and the triangle count of every pre-war roof triples for no visible gain |
| 43 | 6 | The walk drives **MapLibre's own camera** rather than a camera of its own | MapLibre's camera is what deck.gl's overlay and the three.js scene both derive their projections from. One `jumpTo` moves the basemap, the bands, the name-plates, the transit lines and the city together; a separate walk camera means keeping three in step every frame, and the first frame they drift a band parts company with the window it is on | Add a walk camera and sync three projections: ~2 days, and it re-opens the alignment problem sprint 2 closed |
| 44 | 6 | The walker collides with the **footprint**, ours and the context city alike | At eye height a building is its ground floor, and that is what a footprint is. Walking through the anonymous grey building on the corner but not through the one we hold a listing for is worse than no collision — it teaches you not to trust the walls | Collide only with our own buildings: one line, and 40,000 buildings become fog |
| 45 | 6 | Collision resolution runs three passes | On a Manhattan corner two footprints share an edge, and one pass resolves the first while leaving the walker inside the second | Single pass: faster by nothing measurable, and corners stop working |
| 46 | 6 | "Which way is out" is **tested**, not derived from the ring's winding | A walker landing exactly on a wall is called inside by `pointInRing` and has no direction to `nearestEdge`; the fallback normal's sign depends on a winding NYC's data does not guarantee. The push went the wrong way and drove the walker into the building one step at a time until they stood in the middle of it | Normalise winding everywhere instead: it is already done for obstacles, and this is the belt to that's braces. Removing it re-opens a bug that needed 120 marching directions to find |
| 47 | 6 | Pitch clamps at 88°, not 85° | The map's centre is solved from the camera's own view direction, and at exactly 90° that solve divides by zero. MapLibre stops at 85 for the same reason; Explore mode exists to go past that | Lower it to 85: one number, and looking up a facade from the pavement stops being possible, which is the view this mode exists for |
| 48 | 6 | The time step is clamped to 100 ms | A backgrounded tab hands back a delta of several seconds, and an unclamped step puts the walker through the far wall of the block | None — this is a bug guard |
| 49 | 6 | The context-city harness check **polls** rather than sleeping | A fixed nine-second wait passed for three sprints and then failed for reasons unconnected to the code, because the fetch time depends on the cache and the viewport. The natural response to that is to assume the feature broke | None worth having |
| 50 | 7 | Interior mapping is a five-face parallax raycast in tangent space, not a texture | It is what makes glass worth having: a mirror is a surface, a room is a place. The room shifts correctly as you walk past — back wall slow, side walls sweeping — which is the entire cue that says depth. Costs a handful of instructions on fragments already being rasterised: no geometry, no texture, no draw call | Replace with a flat tint: 30 lines removed, and the plan's highest-payoff item goes with it |
| 51 | 7 | The room is a lit box with a ceiling glow and a desk line, and nothing else | Modelling interiors per space by hand is a stated non-goal, and a floor plan invented for a space we hold no drawing of would be the map telling a broker something it does not know | Add furniture: any amount of work, and each piece is a claim about a space we have not seen |
| 52 | 7 | Interiors are off entirely in daylight | A warm speckle across every glass tower at noon is invisible as an effect and visible as noise. Goldenrod is meant to be the only warm thing in the frame | One line to turn on, and it spends legibility for nothing |
| 53 | 7 | The floor plate shares its maths with the band: elevation from `floorHeightFt`, outline from the same cross-section `bandRingAt` uses | If the two ever parted company a broker would step onto the 14th floor and find the Goldenrod band at their ankles. The browser check compares the eye's height against the elevation derived from the **sheet**, not against the plate | Compute it separately: it would work, until the day one of them changed |
| 54 | 7 | Inside a building, collision **inverts** — you may go anywhere on the plate and nowhere beyond it | Walking into the glass stops you at the glass, which is correct and slightly uncanny: you are on the 14th floor | None sensible |
| 55 | 7 | A floor is entered from a space's own card, never by walking into a door | There are no doors, no lobbies and no cores in this model, and inventing one would be a lie about the building. The card is where a broker already is when they care about that floor | Add a door: it needs an interior model this mode explicitly does not have |
| 56 | 7 | Only the building you are standing in is drawn two-sided | A closed shell never needs its inside drawn, and drawing it doubles the fragment cost of the entire city. That trade is worth reversing for exactly one building | Make everything two-sided: one line, and the whole city pays for one room |
| 57 | 7 | Escape from a floor puts you on the street, not straight back to the drone camera | One step back at a time is what the key means everywhere else in this app | Swap the order: two lines |
| 58 | 8 | Cars and people are **neutral grey**, no colour at all | A street full of red and blue cars is the fastest way to lose the one rule: they are small, they move, and moving saturated colour beats static saturated colour every time | Colour them: one line, and availability stops leading in every frame with a street in it |
| 59 | 8 | Agent distribution carries the remainder between roads instead of rounding each independently | With 420 agents over a couple of hundred kilometres of centreline, almost every segment is owed a fraction of one. Rounding each to zero gave Midtown two cars | None — this was a bug |
| 60 | 8 | The roadbed and pavements are drawn in three.js, from the same centrelines the flat map uses | Until this existed the walk put you on a featureless grey plane with cars sliding across it, which reads as a bug rather than as traffic | Remove them and the street level has no street |
| 61 | 8 | Roadbed and pavement are 40% apart in value, not 4% | The first pair were four percent apart and the street did not read at all. The art direction wants clean pale streets with no grime; it is satisfied by near-white surfaces that differ, not by surfaces so close the kerb disappears | Narrow it and the street disappears again |
| 62 | 8 | The scene contains **no `THREE.Light` at all**; everything is shaded explicitly from the atmosphere preset | The traffic's stock Lambert material rendered every car and person black. This camera has its projection matrix assigned directly with an identity world matrix, which three.js's lighting is not built for. Shading by hand is also what keeps the two modes agreeing about how bright a band looks | Debug a light rig for two materials: unknown hours, and it re-introduces a second lighting model beside the one the shaders use |
| 63 | 8 | Frame cost is checked as a **ratio against the same scene without traffic**, not against a millisecond budget | Any absolute number picked on SwiftShader would either fail always or prove nothing. A ratio carries over to hardware | None — an absolute number here is not a measurement |
| 64 | 8 | The surrounding-city harness check asserts on the **context** triangle count, not the total | Once the streets landed, the total cleared the threshold whether or not the surrounding city had arrived. It was a weaker check than it looked | None — this was a weak assertion, found and tightened |
| 65 | 9 | **Sprint 9 trimmed.** The flat map does not get cars, people or the surveyed skyline | deck.gl's overlay is a separate canvas composited above MapLibre's, so three.js traffic underneath it is hidden by the flat map's own ground. Delivering it means either a new deck.gl mesh-layer dependency plus a per-frame loop in the live map's render path, or switching the overlay to `interleaved: true` so both share one buffer. The second changes the render path of a tool brokers use in front of tenants today, in a codebase whose brief records deck.gl's shader and picking passes breaking building clicks twice | **~3 days and a real risk budget.** Interleaved mode is the clean answer and it needs the seven existing browser suites re-run against every layer, plus the picking guards in `mullions.ts` and `atmosphere.ts` re-proved. The owner's call, not mine — it is exactly the "change brokers would see today" the plan reserves |
| 66 | 9 | What ships instead is a **leak guard**: a test that loads the surveyed massing and asserts the flat map's geometry does not move | Explore added a second source of truth about what a building looks like, and `computeBands`, `computeFloorLines` and `buildingRing` are shared. The risk was never that the massing is wrong — it is that it leaks and the flat map changes under a broker with no warning | Delete it and lose the only mechanical guarantee that the two modes stay separate |
